# GART Media — MVP 0.3

Локальный файловый менеджер: Next.js / React / TypeScript, SQLite через Prisma, Sharp. Утверждённый трёхпанельный интерфейс подключён к реальным данным. Node.js 24 LTS, npm, Windows и локальный диск NTFS.

## Запуск

1. Установите зависимости: `npm install`.
2. Создайте локальный `.env` по `.env.example`. Каталог оригиналов должен уже существовать. Код, оригиналы и служебные данные должны быть в отдельных папках; оригиналы и служебные данные — на одном томе для атомарной записи без перезаписи.
3. Выполните `npm run dev`, откройте http://127.0.0.1:3000.
4. Нажмите Scan для индексирования существующих папок и изображений. Повторный Scan не дублирует записи. Альтернатива: `npm run scan` после `npm run db:setup`.

`dev` и `start` автоматически применяют миграции. Production: `npm run build`, затем `npm start`. Сервер слушает только 127.0.0.1; публикация в сеть и удалённый доступ не предусмотрены.

На Windows перед сборкой, обновлением зависимостей и `test:ui` остановите работающий сервер: иначе загруженная Prisma DLL может вызвать EPERM при генерации клиента.

## Хранение

- Оригиналы: `D:/Codex/App mediateka gartmemorial/GART_FILES`.
- SQLite, журнал операций, thumbnails, staging и корзина: `D:/Codex/App mediateka gartmemorial/GART_MEDIA_STATE`.
- Эти данные и `.env` не входят в Git. Резервируйте оба каталога данных при остановленном приложении.
- UI обращается только к серверным API. Файловые операции выполняет LocalStorageProvider.
- Загруженные оригиналы получают уникальное физическое имя; исходное имя сохраняется в SQLite. Содержимое не изменяется. Дубли SHA-256 пропускаются с указанием существующего расположения.
- Scan только читает оригиналы. Уже существующие физические копии индексируются по их путям, но не удаляются и не объединяются автоматически.
- Создание/переименование/загрузка используют блокировку и предварительный журнал AuditLog. При сбое между диском и SQLite незавершённая операция восстанавливается при следующем обращении; неоднозначное состояние блокирует операцию, а не исправляется удалением.

## Возможности и ограничения

Реальные папки, вложенное дерево и breadcrumbs; создание и переименование папки вместе с актуализацией путей потомков; поиск в выбранной папке, gallery/list, сортировка, страницы по 60 изображений; JPG/JPEG/PNG/WEBP, множественная загрузка и drag & drop; thumbnails и свойства файла.

Лимиты сервера: 20 файлов, 50 МБ на изображение, 100 МБ на запрос, 80 мегапикселей. UI автоматически разбивает большой выбор на запросы; ошибка отдельного изображения не отменяет остальные, итог показывает загруженные, пропущенные и ошибочные файлы. При сетевом сбое проверьте обновлённый каталог: повторный импорт защищён checksum. Анимированные изображения не поддерживаются. Неподдерживаемые/повреждённые изображения при Scan пропускаются с предупреждением. Символические ссылки и junction не обходятся. Показатель хранилища отображает занятость всего диска, не только медиатеки.

Во время операций приложения не переименовывайте те же папки в Проводнике. Внешнее перемещение ранее индексированных файлов, Missing/Relink и устранение таких расхождений — отдельный будущий этап. Для больших библиотек Scan синхронный и может занимать время; файловые операции сериализованы.

MediaSet предусмотрен моделью и связан с Project, но редактор серий пока не реализован. Источник загрузки выбирается явно, по умолчанию UNKNOWN. Видео, теги, комментарии, коллекции, избранное, пользователи, Telegram, AI и облачные интеграции отключены. Автоматической публикации нет.

## Выделение и скачивание

Ctrl/Cmd + click переключает файл, Shift + click выбирает диапазон текущей страницы. Checkbox переключает отдельную карточку. «Выбрать всё» выбирает все изображения текущей папки, включая другие страницы, без вложенных папок и независимо от поиска. При переходе в другую папку выделение сбрасывается; Esc и «Снять выделение» очищают его.

Панель выделения позволяет скачать и переместить файлы или отправить их в корзину. Один файл скачивается напрямую; несколько — одним ZIP с исходными именами (совпадения получают числовой суффикс). ZIP папки сохраняет физическое дерево, включая документы и пустые подпапки. Архив генерируется потоково, временного ZIP на сервере нет. Во время скачивания перемещения блокируются; отмена скачивания освобождает потоки и блокировку.

## Корзина

Удаление всегда требует подтверждения. Для непустой папки показаны фактические количества файлов и вложенных папок, включая ещё не индексированные документы. Если содержимое изменилось до подтверждения, потребуется повторное подтверждение.

Объект физически перемещается в `GART_MEDIA_STATE/trash/{id}/payload`. SQLite хранит прежний путь и родителя, дату, состав и новый адрес. Корзина не сканируется как обычная медиатека. Окончательного удаления нет. Резервная копия служебного каталога теперь обязательно включает оригиналы в корзине.

«Корзина» → «Восстановить» возвращает объект в прежнюю родительскую папку. Если родитель был переименован через приложение, используется его актуальный путь. Если родитель сам в корзине — сначала восстановите его. Любой занятый путь считается конфликтом, без замены данных.

Для групповых перемещений конфликты проверяются до начала. Если произошёл сбой посередине, уже завершённые операции сохраняются, следующие останавливаются, UI сообщает ошибку. AuditLog обеспечивает восстановление границы между файловой операцией и SQLite. Не изменяйте те же пути вручную одновременно с приложением.

## Новый проект

Введите номер формата GART-0264, название, год и необязательное описание. «Стандартный проект» создаёт `01_КЛИЕНТСКИЕ_ПРОЕКТЫ/{YEAR}/{Project_ID}_{Название}` и ровно шесть основных подпапок. Конфигурация шаблонов находится в `src/server/project-templates.ts`, а не в UI.

Project и его Folder-записи фиксируются одной транзакцией только после успешного создания структуры. При ошибке Project не появляется в БД; операция явно помечается PROJECT_FAILED в AuditLog. Частично созданные директории намеренно сохраняются для проверки, а не удаляются: сообщение содержит их пути. После проверки их можно индексировать Scan и отправить в корзину. Автоматический повтор поверх частичной структуры не выполняется.

## Проверки

Для зависимости Prisma config закреплён deepmerge-ts 8.0.0 через overrides: исправление GHSA-ggr8-5vv4-36mx. Изменение проверяется миграциями, сборкой и тестами; при обновлении Prisma пересмотрите необходимость override.

`npm run lint`, `npm run typecheck`, `npm test`, `npm run test:ui`.

Браузерные проверки требуют Chromium (`npx playwright install chromium`). Тесты создают отдельные временные каталоги с синтетическими изображениями и SQLite, не используют рабочую медиатеку. UI-проверки включают перезапуск production-сервера и размеры 1440, 1920, 2560 и 390 пикселей. Временные данные сохраняются для диагностики. `GART_SCREENSHOT_DIR` задаёт папку снимков.

Постоянные правила: AGENTS.md и GART_MEDIA_ARCHITECTURE_v1.0_FOR_CODEX.md. Историческое описание UI-прототипа — docs/UI-v0.1.md; его синтетический demo-атлас больше не используется приложением.
