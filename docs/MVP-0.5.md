# MVP 0.5 — 7 сентября 2026

## Изменения

- Общий признак hasContents для sidebar и центральных папок: пустые — контур, непустые — заливка. Дерево, счётчики MediaAsset и PhysicalCopy используются без повторного обхода. Только неизвестные листья проверяются через StorageProvider.hasEntries: чтение первой записи каталога, без рекурсии и чтения содержимого файлов.
- Рамочное выделение мышью с пустого места центральной области. Обычная рамка заменяет выбор, Ctrl/Cmd переключает попадания относительно начального выбора. Drag с карточки не запускает рамку. Панель выделения сохраняет место, чтобы карточки не сдвигались во время жеста. Ctrl-click, Shift-click, checkbox и Select All сохранены.
- Внутреннее перемещение выделенной группы на папки sidebar и центра. Невыделенная карточка становится единственным payload; есть счётчик, подсветка доступной цели. Текущая папка недоступна. Используется прежняя безопасная операция move с AuditLog, проверкой конфликтов и StorageProvider.
- Внутренний MIME application/x-gart-media-assets плюс токен активного жеста отделяют move от upload. На пустой области такой drag завершается без загрузки. Внешний Files drag по-прежнему запускает именование и ingest.
- Поиск текущей папки использует общий searchKey: Unicode NFKC, trim, lowercase. Сравниваются current storedFilename и originalFilename; имена папок в центре нормализуются так же. Для кириллицы не используется нечувствительность SQLite LIKE, которая ограничена ASCII. Пагинация применяется после сравнения лёгкой проекции имён выбранной папки, не после фильтрации одной страницы. Title, теги и поиск по проектам не добавлены: они не участвовали в текущем поиске.

## Scan: причина и исправление

В рабочей базе обнаружены 12 пар уже зарегистрированных MediaAsset с одинаковым SHA-256. Раньше известный path попадал в ветку unchanged до проверки дубля содержимого, поэтому такие пары не отображались.

Теперь SHA-256 вычисляется для прочитанных изображений до поиска дубля и до проверки формата нового файла. Новый путь с новым SHA регистрируется как MediaAsset; новый путь с известным SHA — как PhysicalCopy. Повторный Scan сохраняет тот же ID копии.

Старые независимые активы с одинаковым SHA показываются как legacy-дубли, без автоматического объединения, удаления или изменения ID. Отчёт содержит имя и путь найденного файла, существующий MediaAsset, его имя/путь и checksum. Для legacy используются существующие MediaAsset и AuditLog, дополнительные записи PhysicalCopy не создаются. Решение «оставить» журналируется; Trash использует текущую безопасную операцию MediaAsset и поддерживает restore. Для новых PhysicalCopy сохранены их действия и корзина. Перед действием обе физические копии повторно проверяются по SHA.

Изменение схемы SQLite не потребовалось. Оригиналы остаются отдельно от кода. До проверок сохранена резервная копия GART_MEDIA_STATE/media-before-mvp05-20260907.db.
